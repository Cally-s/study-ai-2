# Feedback and Revision

> Authorized stakeholder feedback is evidence, not an automatic release instruction. Step 28 records student interpretation, uncertainty, hidden work, and resulting scope or release conditions.

Label feedback real, synthetic, automated, interpreted, or unverified. Connect test or feedback → problem → hypothesis → change → expected effect → retest → keep, modify, revert, or remove. Preserve workflow, prompt, data, source, test, review, contribution, and prototype versions.

## Card freshness

Feedback-driven project changes mark affected AI System Card sections for review and create a new version rather than silently rewriting approved narrative.

## Architecture versions

Feedback changes architecture only through reviewed decisions, a new immutable version, mapped retests, and a corresponding stale AI System Card.

## Fairness revisions

Mitigation links findings to a reviewed change, comparable retest, before/after counts, new-harm review, residual risk, new system versions, and a new fairness version.

## Step 27 canonical cycle

Iteration and Feedback Studio reuses project prototypes, tests, feedback dispositions and revision decisions to preserve baseline/change/new-version/retest/limitation history instead of duplicating them.
