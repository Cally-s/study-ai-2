# Data Responsibility Studio

> Step 28 links permissions, access, external processing, retention, and deletion into privacy, power, release, and reversibility reasoning.

Purpose: plan and approve each dataset version and use before collection, upload, import, connection, scraping, recording, embedding, indexing, external processing, prototyping, sharing, or export. It asks the ten exact questions from “What data are needed?” through “Could synthetic or public data be used instead?” The gate absolutely prohibits confidential school, medical, counselling, and financial records without classroom-role override. This static prototype lacks authoritative production upload/connector/offline enforcement.

## Fairness scenarios

Use synthetic safe samples or authorized privacy-reviewed data, disclose missing contexts and quality limits, and avoid protected-trait inference. Data changes from mitigation create a new Data Plan/Dataset version.

## Iteration data changes

Dataset, field, purpose, permission, access, retention or deletion changes require a new Data Plan/Dataset version before retesting or functional use.
