# AI System Card

## Step 59 public projection
A portfolio uses a sanitized static projection of one submitted card version with limitations and provenance. Secrets, private prompts, service URLs, confidential data references, source code paths, and teacher comments never enter it.

## Step 58 portfolio use
Submitted System Cards may evidence workflow, data responsibility, testing, oversight, limitations, failure handling, and conditions not to use. Private versions and secret-bearing fields remain excluded.

> The confirmed Step 28 reflection marks the System Card for an update to limitations, oversight, conditions not to use, and deployment status; it does not create another card.

Canonical living documentation for the current project and prototype version. It contains the twenty exact required sections from Project name through Conditions under which the system should not be used. Material project changes mark it stale; student-reviewed new versions preserve immutable approved/exported history. The current static implementation is in-memory and cannot certify or deploy.

## Architecture updates

Confirmed Step 24 designs update model/system, data, output, error, privacy, accessibility, oversight, testing, feedback, limitation, and prohibited-use sections. Architecture changes mark the card stale rather than rewriting it.

## Data-plan updates

Dataset, permission, quality, coverage, retention, access, deletion, or external-service changes mark Input Data, Data Permissions, Privacy, Limitations, Fairness, and Conditions Not to Use sections for review.

## Fairness updates

Current findings, limitations, errors, accessibility gaps, reviewer limits, residual risk, and deployment conditions update the card and cannot be hidden from public-safe summaries.

## Iteration freshness

Material revisions mark affected card sections for student review. Final limitations, unresolved tests, changed components/data/users and conditions not to use remain visible.

## Step 56 teacher review
Only intentionally submitted or shared cards are reviewable. Feedback is stored separately from the immutable student card; no automatic score, competency decision, diagnosis, honesty inference, or edit is allowed.
