# Low-Bandwidth and Offline Options

> Step 68 release mapping: full packages, Low-Bandwidth delivery, local progress, and synchronization belong to Stage 6 and depend on Stages 1–5 records. These capabilities remain Internal Testing; no service worker, durable store, signer, or sync server exists.

> Step 67 integration: rules and neutral reasons remain available in text-first Low-Bandwidth presentation. Offline factual work requires a pending-internet label; prompts, teacher questions, review requests, and after-test actions never activate or send automatically on reconnection.

> Step 66 integration: Low-Bandwidth Mode uses the same validated response in a text-first card. Offline blocks before cloud generation, displays **AI Coach unavailable offline**, preserves the draft, never queues an automatic send, and retains **Verification pending internet access**.

Step 64 preserves meaningful AI-literacy access when connectivity is slow, intermittent, expensive, or unavailable. Students control text-first mode and can use compressed media, signed packages, worksheets, offline prompt/integrity practice, transcript-backed audio, local drafts, and reconnect synchronization without changing criteria or age settings. Offline cloud AI is clearly unavailable and static content is labelled downloaded. Connectivity is never exposed, ranked, or used to infer disability, income, location, ability, or risk. Every offline source activity displays exactly **Verification pending internet access** until authorized current checks finish.
