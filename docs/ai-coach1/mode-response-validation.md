# Mode Response Validation

> Quiz validation enforces one objective/question, selected topic/type/difficulty, safe provenance, isolated key, no future payload, bilingual/accessibility equivalence, feedback timing, and no answer/metadata/ARIA/offline leakage.

> Challenge output validation enforces one material primary challenge, an identified supported basis, verified conflicting evidence, labelled hypotheticals, exact ordered sections, defend-or-revise, waiting, and no praise/disagreement/rewrite/profile leakage.

> Reasoning output validates exact section order, referenced student steps, earliest dependency issue, calibrated uncertainty, one repair question, student verification, no replacement/answer/all-errors list, and waiting.

> Similar Example checks skill/process alignment, content/result/source/data/code/copyright distance, one example, all required sections, one transfer prompt, waiting, and hidden/original-answer absence.

> Step 32 rejects multiple semantic tasks, compound/question-dump structures, self-answers, answer-embedded acknowledgements/examples/metadata, plans, takeover corrections, missing waiting, and unlinked adaptation.

> Progressive validation checks exact next level, one hint, level-specific boundaries, waiting, cumulative leakage, meaningful work after Guided Setup, and prohibited hidden fields.

Incremental and final validation checks direct and equivalent answers, hidden/accessibility/tool payloads, multiple hints/questions, self-answering questions, cumulative leakage, meaning/term preservation, example distance, replacement solutions, unsupported challenges, early quiz answers, fabricated sources/quotations, and policy/session bypass. Blocked bodies never reach client payloads, history, receipts, analytics, notifications, print, or exports; only privacy-safe codes are audited.
