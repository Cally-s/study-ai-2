# Shared Prerequisite Repair

One versioned path may support several work items through separate task links. Each link records relationship, relevance, earliest required date and active state. The earliest relevant deadline governs planning.

Student, concept, content version and current horizon form the deduplication boundary. A new path is allowed only when the previous one is outdated, the required method differs, the student requests a permitted new example, or evidence shows the earlier repair was insufficient.

Time is counted once. Reuse does not collapse task records or disclose one task’s private details through another.
