# Prerequisite Repair Accessibility

The repair screen uses semantic headings, an ordered five-stage list, native buttons/inputs, visible focus, status and alert regions, accessible text for mathematics, keyboard entry and text-based hints. Progress is announced as a stage, never a mastery percentage.

Contracts cover 200% zoom, roughly 320 CSS pixels, Extra-Large text, increased spacing, high contrast, forced colours, Reduced Motion, Animation Free, Simplified Layout, dyslexia-friendly display, reading ruler, text-only and low-bandwidth presentation, RTL and Language Bridge ordering.

Listen and bilingual controls are exposed, but production TTS/translation integration is not claimed. Speech-to-Text must retain editable review before submission. No video, audio, camera, microphone, pointer, hover, dragging, colour perception or timed answer is required.

Manual browser, screen-reader, math-speech, zoom, contrast, language, network and representative-user results remain NOT RUN.
