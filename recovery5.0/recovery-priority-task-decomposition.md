# Recovery Priority Task Decomposition

A task does not become less important merely because it is large. StudySpark should divide it into smaller, observable actions and schedule those actions realistically.

Estimated effort is excluded from the importance score. It affects feasibility, scheduling and whether decomposition is required. The parent task keeps its priority and authority state; each bounded next action receives its own definition of done, dependency, duration range and actionability review. Decomposition cannot fabricate completion, bypass a blocker or consume protected sleep, breaks, commitments or buffer.
