# Learning Mode Security

> Step 36 validates tenant ownership, snapshots, policy, immutable configuration, question provenance/quality, key authorization, feedback timing, tools, concurrency, idempotency, serializers, and offline/account isolation.

> Step 35 validates tenant ownership, immutable snapshots and versions, provenance, policy, materiality, challenge/source basis, tools, concurrency, and idempotency while treating student and retrieved content as untrusted.

> Step 34 adds confirmed provenance, immutable work versions, explicit dependency references, first-issue ordering, minimum-input tool filtering and targeted revision enforcement.

> Step 33 adds trusted skill/boundary/context state, distance/copyright review, restricted tools, direct generation, no hidden solution, ownership and idempotency.

> Step 32 adds actual-response message linkage, one-question schemas, waiting locks, no question queue, restricted tools, and tenant/idempotency enforcement.

> Hint transitions use trusted snapshot state, server policy maximum, cumulative disclosure, answer boundary, ownership, idempotency, and optimistic concurrency.

> Step 30 adds pre-generation contract/tool enforcement, direct schemas, streaming/final validation, safe regeneration, and no-hidden-answer guarantees.

Server state, trusted versioned definitions, authoritative policy resolution, immutable message snapshots, response validation, ownership, tenant isolation, idempotency, and optimistic row versions protect the contract. Client labels and client-supplied modes are not trusted. Prompts, retrieved content, uploads, webpages, and tool results cannot override the mode. Privacy-safe logging records mode identifiers and conflict categories, not private text, hidden reasoning, system prompts, or provider secrets.
