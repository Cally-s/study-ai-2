# Testing

Test normal, edge, ambiguous, missing, outdated, unsupported, injection, privacy, harmful, high-stakes, accessible, low-bandwidth, multilingual, misuse, escalation, refusal, and correction cases. Record ground truth, accuracy, safety, review, severity, analysis, revision, and retest.

## System-card evidence

Card testing claims link the prototype and test versions, normal and failure cases, ground truth, results, unresolved failures, and latest date. Implemented never means tested automatically.

## Architecture-derived tests

Error points, privacy controls, retrieval failures, validation failures, review unavailability, service outages, and fallbacks produce reviewable test candidates rather than automatic results.

## Data-plan gate

Tests and functional prototypes use only the confirmed dataset version and approved purpose; permission withdrawal or plan staleness blocks new processing and marks outputs for review.

## Fairness test records

Every run identifies exact project, architecture, dataset, prompt/processing, model/service, validator, interface, and prototype versions plus counts, denominators, severity, correction burden, review, and student analysis.

## Honest iteration testing

Preserve failed/partial/inconclusive/invalid/blocked/not-run results, expected-before-result records and exact versions; rerun original, regression and new-harm cases after change.
